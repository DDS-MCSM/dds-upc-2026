Bloc 1 · Data Science en seguretat

Dels SIEM a l'anàlisi de dades

Fa vint anys, «seguretat i dades» volia dir un SIEM: un sol producte que ho recollia tot i et deia què mirar.

Un SIEM fa sis coses: agrega dades de moltes fonts, les correlaciona, genera alertes, analitza el comportament, dibuixa dashboards i produeix informes de compliment.

Això és bo i continua sent necessari. Però només respon les preguntes que algú va programar. Quan la pregunta és nova, o és la teva, toca fer anàlisi de dades.

L'escala de l'analítica
Descriure què ha passat → entendre per què → predir què passarà → decidir què fer. Cada pas demana més dades, més cura i més preguntes.
Bloc 1 · Data Science

Fer ciència de dades no és fer-ne màgia

Un matís que convé tenir clar des del primer dia.

@kwbroman
«Quan els físics fan matemàtiques, no diuen que fan “ciència dels números”. Fan matemàtiques. Si analitzes dades, fas estadística. Pots dir-ne ciència de dades, informàtica o analítica, però continua sent estadística.»
  • No cal cap fórmula màgica: cal mètode, i saber distingir una xifra d'una evidència.
  • El que sí és nou és l'escala (milions de files), l'eina (codi i no fulls de càlcul) i el context (seguretat, on una xifra falsa té conseqüències).
Bloc 1 · Les quatre fases

Pregunta, dades, anàlisi, comunicació

Una anàlisi de dades en seguretat és, sempre, aquest recorregut. Mesurable en acabar: saber-les dir.

01
La pregunta és el que importa
Abans de tocar res: què vull saber i què faré amb la resposta? «Quantes vulnerabilitats hi ha?» és una pregunta pobra; «quines debilitats es repeteixen més i per què?», una altra.
02
Les dades
D'on surten, qui les manté, de quan són, què no diuen. Sense això no hi ha anàlisi, només càlcul.
03
L'anàlisi
Netejar, explorar, resumir, modelar. Aquí hi viuen l'estadística i el machine learning (S4).
04
La comunicació
Un gràfic, una taula, un informe que algú altre pugui llegir, discutir i regenerar (S2).

Bloc 3 · git (1 de 2)

Què és git i què no cal saber-ne avui

Un sistema de control de versions: guarda cada canvi, qui l'ha fet i quan. Avui només n'aprendreu el que cal per lliurar.

Tres llocs on viuen els vostres fitxers:

  • El directori de treball: la carpeta que veieu a l'explorador.
  • El repositori local: l'historial, a la carpeta oculta .git del vostre ordinador.
  • El repositori remot: la còpia a GitHub.

Entre el treball i el repositori hi ha l'àrea de preparació (staging): triar quins canvis entren al proper commit.

Fora d'abast avui
Branques, merge, rebase, HEAD, conflictes. Ja els trobareu quan els necessiteu; l'exercici d'avui no els demana.
Bloc 3 · git (2 de 2)

El cicle: clone, add, commit, push

20 minuts, amb demo en directe. Després ho feu vosaltres a l'exercici.

  1. git cloneBaixa el repositori de GitHub a l'ordinador. Es fa una sola vegada.
  2. git addMarca el fitxer que ha canviat: entra a l'àrea de preparació.
  3. git commit -m "…"Desa els canvis preparats a l'historial local, amb un missatge.
  4. git pushEnvia els commits a GitHub.
Què heu de veure
  • git status: què ha canviat i què està preparat.
  • git log --oneline: l'historial.
  • A GitHub, el fitxer i el commit que acabeu de fer.
  • Un missatge que digui què: «Exercici 0: primera consulta», no «canvis».
Bloc 4 · R en un minut

Només el que cal per a l'exercici 0

R bàsic de debò, a la S2. Avui, cinc coses.

x <- 5                         # assignar: el nom a l'esquerra, el valor a la dreta
v <- c(9.8, 7.5, 5.3)          # un vector: tot a R és un vector
mean(v)                         # una funció: nom i parèntesis

library(mitre)                  # carregar un paquet ja instal·lat
nrow(cve.nist)                  # files d'una taula (data frame)
cve.nist$cve.id                 # $ en tria una columna
head(cve.nist$cve.id)           # les primeres sis

?mean                           # l'ajuda d'una funció
Diferència clau: install.packages("x") descarrega un paquet, una sola vegada; library(x) el carrega, a cada sessió.

Bloc compliance · 10 min

Abans de tancar

Les dades de seguretat, de qui són?

Concepte
Un CVE és públic: qualsevol pot mirar-lo, citar-lo i comparar-lo. Un inventari del programari d'un portàtil no: diu què hi has instal·lat, quan i amb quines versions. El mateix tipus de dada, dues respostes diferents.
Regla
Les dades dels alumnes no surten del vostre portàtil. El repositori de l'assignatura ja ho té previst: el .gitignore exclou *.json i outputs/.
Enllaç
A la S3 farem un inventari del vostre programari. Avui ja heu de poder dir quin dels dos casos és cada dada abans de fer-li un push.
