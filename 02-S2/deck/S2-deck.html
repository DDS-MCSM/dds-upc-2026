Bloc 1 · Reproduïbilitat

Mateixes dades i mateix codi, mateix resultat

Reproduir és que una altra persona, o tu d'aquí a sis mesos, torni a obtenir el resultat sense que li expliquis res de viva veu.

Per què importa en seguretat: un informe d'incident, una validació de CPE o un recompte de vulnerabilitats són evidència. Una xifra que no es pot tornar a calcular és una opinió.

  • Què pot fer canviar el resultat sense que ho notis: la versió del paquet, la data de les dades, la zona horària, una llavor aleatòria (set.seed), l'ordre en què has executat les cel·les.
  • Un exemple d'avui: l'any d'un CVE canvia per a 100 d'ells segons la zona horària del teu ordinador.
Prova de foc
Tanca l'entorn, obre'l de nou i fes Knit. Si el resultat no és el mateix, l'informe no és reproduïble.
Bloc 1 · Les quatre regles

Quatre regles, quatre comprovacions

Les quatre regles de la reproduïbilitat, aplicades a l'exercici d'avui.

01
Projecte portable
Eines obertes, rutes relatives, cap setwd("C:/..."). Si ho obre un company, funciona.
02
Cap manipulació manual de dades
Cap cel·la editada a mà ni Excel pel mig: tot el que passa a les dades és codi.
03
Resultats connectats amb el text
Una xifra al text és codi en línia (`r nrow(x)`), no un número copiat.
04
Control de versions
El .Rmd i el .html viuen a git, amb un commit per cada canvi que importa.
Bloc 2 · Literate programming

Text i codi al mateix fitxer

L'article explica l'anàlisi (Markdown); els blocs de codi la fan (R). Quan el document es construeix, el codi s'executa i els resultats entren al text.

  • Text i codi plegats: més fàcil treballar en equip i trobar errors.
  • El codi és «viu»: si canvia la dada o un paràmetre, canvia l'informe.
  • Markdown: format mínim (títols, llistes, cursiva, negreta) que es converteix a HTML i a altres formats.
# Títol de nivell 1
## Secció
Text amb *cursiva* i **negreta**.

- element de llista
- un altre

[enllaç](https://github.com/motherhack3r/mitre)
Bloc 2 · R Markdown i knitr

Un .Rmd té tres parts

Capçalera YAML, text en Markdown i chunks de codi. knitr executa els chunks i en fa un Markdown; pandoc el converteix a HTML, PDF o Word.

---

output: html_document
---

Text introductori en Markdown.

```{r dades}
hist(cve.nist$cvss3.score)
```

Hi ha `r nrow(cve.nist)` CVE a la taula.

Bloc 4 · R bàsic (1 de 3)

Vectors, tipus, NA, factors i dates

Tot a R és un vector. Un vector només té un tipus; si en barregeu, R en tria un (coerció).

sev <- c(9.8, 7.5, NA, 5.3)       # numeric; NA = valor que falta
is.na(sev)                       # FALSE FALSE TRUE FALSE
mean(sev, na.rm = TRUE)          # 7.533: sense na.rm, el resultat seria NA

c(1.2, "a")                      # "1.2" "a": tot passa a character

nivell <- factor(c("HIGH", "LOW", "HIGH"), levels = c("LOW", "MEDIUM", "HIGH"))
table(nivell)                    # compta per categoria

d <- as.Date("2021-12-10")       # una data, no un text
format(d, "%Y")                  # "2021"
Trampa habitual: una columna que sembla numèrica però és text. Comprova-ho amb class() o str() abans de calcular res.
Bloc 4 · R bàsic (2 de 3)

Llistes, data frames i subsetting

Una llista barreja tipus; un data frame és una llista de columnes de la mateixa llargada. cve.nist és un data frame.

x <- list(id = "CVE-2021-44228", cwe = c("CWE-20", "CWE-400", "CWE-502"))
x$cwe[3]                         # "CWE-502"
x[["id"]]                        # "CVE-2021-44228"

cve <- mitre::cve.nist
nrow(cve); ncol(cve)             # files i columnes
cve$cvss3.score[1:5]             # una columna, cinc primers valors
cve[cve$cve.id == "CVE-2021-44228", c("cve.id", "cvss3.score")]   # fila(es), columnes
mean(cve$cvss3.score >= 9, na.rm = TRUE)   # operació vectoritzada: sense bucle
[ torna el mateix tipus d'objecte; [[ i $ en treuen un element. Dins del bracket: files, columnes.
Bloc 4 · R bàsic (3 de 3)

Funcions i el mínim de tidyverse

Una funció és un objecte més. El pipe |> encadena passos de lectura esquerra-dreta. Amb això en teniu prou per a la S3 i la S4.

pct_critic <- function(x, llindar = 9) mean(x >= llindar, na.rm = TRUE)
pct_critic(cve$cvss3.score)      # 0.151 sobre els CVE amb puntuació

library(dplyr)
cve |>
  filter(!is.na(cvss3.score)) |>     # files que compleixen una condició
  mutate(critic = cvss3.score >= 9) |>   # columna nova
  count(critic)                      # comptar per valor
No ho veurem avui: bucles, while, scoping lèxic. Ja els trobareu a les referències si els necessiteu.
